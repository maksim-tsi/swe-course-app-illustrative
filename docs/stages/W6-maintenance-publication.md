# W6 — Maintain, hand over and publish the example

**Lectures:** L16–L18. **Engineering budget:** at most 8 instructor hours. **Input:** W5 release and recovery evidence. **Tool illustration:** re-open the same repository with another available harness and confirm that shared instructions, skills and evidence remain understandable; no agent comparison is graded.

## Instructor task

1. Take one small post-release request or observed defect. Map its impact, add a characterization/regression check for retained behaviour and make a bounded patch.
2. Update the runbook with setup, release identity, smoke check, rollback/restore limits and handover contacts or responsibilities. Verify the replacement while retiring only an old **test** endpoint/version; retain source history, artifacts and synthetic data as required.
3. After an explicit instructor operational decision, publish a course-accessible teaching instance with synthetic data and access controls appropriate to its write operations. Check the actual URL, revision and one read/write or restricted-write smoke path. If publication is blocked, record it as blocked rather than claiming completion.
4. Record one process improvement based on the six-stage evidence and a final accept/revise decision.

## Done when

The maintenance change, handover, safe retirement and accessible published revision are evidenced separately. A GitHub source repository alone is not proof of a running app. Do not expose real customer data or a writable unauthenticated service.
