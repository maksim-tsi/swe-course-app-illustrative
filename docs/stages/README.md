# Instructor demonstration stages

These are **instructor tasks in one illustrative repository**, not student homework H1–H6. Each stage follows the corresponding three course lectures and prepares the method for the separate student assignment. The instructor operates all tools. AI roles can assist, but the instructor reviews and decides. Each stage has an upper bound of **8 engineering hours**, including code, checks, documentation and review; the workshop shows a roughly 40-minute slice. Preserve the revision/evidence left by the prior stage.

| Stage | Lectures | Instructor result | Suggested demonstration tools |
|---|---|---|---|
| [W1](W1-initiation.md) | L1–L3 | ADR, contract and skeleton | OpenCode; optional VM/model setup |
| [W2](W2-usable-slice.md) | L4–L6 | Browser-to-state booking and reproducible startup | GitHub CLI for issue/PR evidence, plus an available AI agent |
| [W3](W3-test-and-early-release.md) | L7–L9 | Better test oracles and early release | Codex as an optional agent example |
| [W4](W4-feedback-reschedule.md) | L10–L12 | Stateful feedback change and real integration | Antigravity as an optional agent example |
| [W5](W5-operational-release.md) | L13–L15 | Trust boundary and isolated recovery | Reuse agent/CLI with operational review |
| [W6](W6-maintenance-publication.md) | L16–L18 | Maintenance, handover and publication | Cross-tool handoff using shared repo instructions |

`gh` is the GitHub CLI, not an AI harness. Four named tools do not require six unique AI products; use them where they clarify a stage, and keep a manual/ordinary-tool route. Tool access, model/provider setup and vendor comparison are not graded student requirements. See [the test plan](../test-plan.md) and [acceptance plan](../acceptance-plan.md) for the course-wide trace.
