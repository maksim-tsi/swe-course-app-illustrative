# Architecture Decision Records

**No ADR exists at the pre-W1 baseline.** `ADR-001` is TODO for the first instructor demonstration. The instructor will evaluate the proposed modular monolith in [the architecture note](../architecture.md), compare one viable alternative, make the decision and record its consequences before relying on it in code.

Use a short numbered Markdown file such as `0001-application-boundary.md` with: title, date/status, context and quality risk, decision, one considered alternative, consequences/trade-offs, and evidence or assumptions. Mark a proposal as proposed until the instructor accepts it. Link affected requirements and checks. Later decisions amend or supersede via a new record; preserve old records and Git history.

W1 must also state the interval/allocation assumptions that are material to the chosen boundary. Do not create an empty ADR template labelled accepted or backdate a decision.
