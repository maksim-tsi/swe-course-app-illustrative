# Architecture Decision Records

The first [application-boundary ADR](0001-application-boundary.md) is a **W1 proposal**, not an accepted instructor decision. It compares the proposed modular monolith with a separately deployed service and records the W1 contract and future interval/allocation assumptions. The instructor will record an accept, revise or reject decision after reviewing the feature PR.

Use a short numbered Markdown file such as `0001-application-boundary.md` with: title, date/status, context and quality risk, decision, one considered alternative, consequences/trade-offs, and evidence or assumptions. Mark a proposal as proposed until the instructor accepts it. Link affected requirements and checks. Later decisions amend or supersede via a new record; preserve old records and Git history.

W1 states the interval/allocation assumptions material to the proposed boundary. Do not label a proposal accepted or backdate a decision.
